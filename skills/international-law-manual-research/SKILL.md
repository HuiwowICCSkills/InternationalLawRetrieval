# 国际法人工补检

本技能负责自动路径未覆盖的人工操作。它是检索工作流和离线交接助手，不是已实现的登录或浏览器控制工具。支持 GIL、ICL 的 JSON 检索报告；没有报告时按具体目标查 [渠道与动作](references/routes.json)。清单中的入口不等于取得了内容。

## 从检索报告接手

```powershell
python -X utf8 '<本技能目录>/scripts/handoff.py' --input './gil-results.json' --out './manual-tasks.json'
python -X utf8 '<本技能目录>/scripts/handoff.py' --input './icl-results.json' --format markdown --out './manual-tasks.md'
```

脚本只读已有 JSON，不联网。支持 `--domain gil|icl` 明确来源；正常报告可自动识别。它会给每项动作保留查询词、渠道状态、警告、适用条件、入口和回收材料要求；元数据成功或使用替代语料时生成条件性任务，不强称必须人工操作。

1. 明确本次缺口：全文、指定版次、完整数据库覆盖、最新状态，或仅某个下载失败。先检查报告中已有正文/PDF，已满足的材料不要再次索取。
2. 按 `condition` 决定任务是否需要执行。本次自动请求失败只能说明本次受限；历史 403、旧书籍状态不表示永久不可用。网络超时、分页与抓取预算不足可先用原自动工具处理；OCR 通常可自动化，不一律推给用户。
3. 有授权且已可用的浏览器会话时，可用当前提供的浏览器能力辅助公开检索；操作前遵循对应工具/技能说明。本技能本身不要求打开浏览器。用户仍要求不依赖浏览器时，输出精确的人工步骤，由用户完成需要身份的环节，再继续处理取得的文件。
4. 登录、机构单点登录和验证码交由用户操作；不索取密码、验证码、Cookie。不要把网页访问受限当作订阅已具备。购买、注册、发邮件或文献传递申请，仅在用户明确要求对应动作时执行；整理申请信息本身可直接完成。
5. 对取得的材料，记录题名、作者/机构、案件号或文号、日期、语言、版次、官方/镜像来源、实际访问 URL、取得时间、文件 SHA-256，以及正文/预览/目录/仅元数据状态。页码须区分 PDF 页与印刷页。以真实文件核验成功，不以点击过按钮作为完成。
6. 用户提供 PDF/HTML 后，交回 GIL/ICL 的提取流程或现有本地书籍流程；仅在用户要求入库时再按本地资料库自身的维护规则导入。不要为了补检自动扫描或改动本地资料库。

## 职责与记录

- 广外统一身份认证和图书馆 VPN 会话已拆为独立技能 [gdufs-auth-session](../gdufs-auth-session/SKILL.md)。HeinOnline 等机构来源先调用该技能的 `ensure` 复用会话；本技能只处理仍然需要验证码、扫码或人工确认的步骤。
- GIL 的公开 API、WordPress 正文、目录/网页/PDF、缓存检索仍由 `gil-research` 处理。
- ICL 的 Legal Tools、CLD、Lexsitus、TOAEP 和 ICRC 书籍替代语料仍由 `icl-research` 处理；UCR 本库登录、官方实时状态和未被镜像覆盖的内容在这里补检。
- 原站有访问限制的渠道：先用精确查询、具体文号/案件号/DOI；不要反复探测同一拒绝入口，也不要冒充已恢复接口。
- 历史 Klamberg 网站失效不等于可以靠人工登录恢复；只有需要原站特定旧内容时，才核查可验证的公开归档或馆藏，并承认可能无法取得。
- 书籍获取见 [书籍补检](references/books.md)。13 个书籍技能只是检索入口，不表示已拥有 13 本全文；状态需按实际文件刷新。

任务状态使用：`pending`、`waiting_for_user_login`、`located_metadata`、`acquired_preview`、`acquired_fulltext`、`unavailable`。未拿到全文就不能标为 `acquired_fulltext`；外部访问状态只能作为本次观察。

回交时报告：已取得材料与对应任务、仍缺材料及原因、证据文件/URL、版次语言、正文提取/OCR 状态。不要把浏览器阅读许可推定为允许导出原文件；不支持导出的平台可标为“仅在线阅读”。
